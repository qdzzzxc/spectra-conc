# Python quality tooling

Источник конфигов: проект ml/templates/linter_configs во внутреннем GitLab. Адрес хоста брать из remote текущего репозитория, а не из этого файла.

Конфиги брать только оттуда: там лежит актуальная версия. Копий в этом скилле нет намеренно. Если проект недоступен, не восстанавливать конфиги по памяти и не сочинять их: сообщить о недоступности источника, а изменения ограничить тем, что уже есть в репозитории.

Конфиги из источника — общие шаблоны, их нужно адаптировать под проект. В частности, привести Python target к командному baseline 3.12+, если в шаблоне указана более старая версия.

## Dependencies

Добавлять инструменты качества в extra dev с версиями, совместимыми с текущим репозиторием:

~~~toml
[project.optional-dependencies]
dev = [
    "mypy",
    "nbstripout",
    "pre-commit",
    "ruff",
]
~~~

Использовать uv sync --extra dev. Не вызывать pip, Poetry или Pipenv напрямую. Сохранять существующие пины, если они осознанные, и обновлять lock-файл только когда изменение зависимостей входит в задачу.

## Ruff

- Ставить target-version в py312, если проект не обязан поддерживать более строгий контракт версий.
- В known-first-party указывать реальный import-пакет.
- Сохранять ignore, совместимые с форматтером.
- Проверять импорты, современную типизацию, аннотации возврата, стиль pytest, обработку исключений, безопасность, логирование, производительность и докстринги — в объёме, уместном для проекта.
- Для тестов и примеров предпочитать per-file-ignores полному исключению из проверки.
- Обосновывать каждый глобальный ignore; не глушить целое семейство правил, чтобы спрятать существующие находки.

Запуск:

~~~text
uv run ruff check .
uv run ruff format --check .
~~~

Использовать --fix и ruff format только когда изменение файлов входит в задачу.

## mypy

- Ставить python_version 3.12.
- Включать strict и explicit_package_bases.
- Использовать плагин Pydantic, если проект использует Pydantic.
- Сохранять warn_unused_ignores, warn_return_any, warn_unused_configs и no_implicit_optional.
- Сужать exclude до сгенерированного или намеренно нетипизированного кода.
- Не использовать ignore_missing_imports вместо типов проекта, если пакет поставляет стабы.

Запускать uv run mypy . или более узкие пути пакетов, принятые в репозитории.

## pre-commit

Базовый набор из источника выполняет:

- ruff check и ruff format;
- локальный mypy через uv;
- проверку синтаксиса и валидацию YAML, JSON и TOML;
- проверки пробелов, конца файла, конфликтов регистра, маркеров конфликта, приватных ключей и крупных файлов;
- gitleaks;
- запрет управляющих символов bidi;
- nbstripout для ноутбуков.

Установка и запуск:

~~~text
uv run pre-commit install
uv run pre-commit run --all-files
~~~

Пинить ревизии хуков и обновлять их осознанно. Не использовать mypy --install-types внутри хука: это добавляет зависящую от сети мутацию во время проверки. Стабы объявлять в dev-зависимостях.

## Ignore files and large artifacts

- Коммитить uv.lock для приложений и бинарных пакетов, если правила репозитория не требуют иного.
- Игнорировать виртуальные окружения, кэши, локальные секреты, отчёты, состояние редактора, локальные базы и результаты сборки.
- Не игнорировать конфигурацию, которая нужна всем разработчикам.
- Для весов, датасетов, ноутбуков, архивов и изображений использовать Git LFS, когда это оправдано размером; коммитить .gitattributes.
- Считать check-added-large-files ранним предупреждением, а не заменой политики LFS.

## CI parity

В CI выполнять ту же семантику Ruff, mypy и pre-commit, что и локально. Если CI вызывает инструменты по отдельности, держать пути и файлы конфигурации согласованными с локальными хуками. Зелёный локальный хук, который проверяет меньше файлов, чем CI, — это дрейф конфигурации.
