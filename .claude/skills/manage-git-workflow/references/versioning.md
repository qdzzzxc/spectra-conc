# Versioning and changelog

Использовать Semantic Versioning и Keep a Changelog.

## Choosing a version

- MAJOR: несовместимое для пользователя/API изменение. Обнулить MINOR и PATCH.
- MINOR: обратно совместимая новая функциональность. Обнулить PATCH.
- PATCH: обратно совместимый bug fix.
- Pre-release: добавить после дефиса, например 1.0.0-alpha.1; приоритет ниже финального 1.0.0.
- Build metadata: добавить после плюса, например 1.0.0+001; не менять precedence.

Выбирать bump по реальному пользовательскому контракту. BREAKING CHANGE в commit не требует MAJOR, если внешний contract фактически совместим; и наоборот, незамеченная несовместимость требует MAJOR.

## CHANGELOG location and top section

- Хранить CHANGELOG.md в корне repository.
- Держать сверху секцию:

~~~markdown
## [Unreleased] / Невыпущенное
~~~

- После релиза создавать секцию:

~~~markdown
## [X.Y.Z] - YYYY-MM-DD
~~~

- Писать для пользователя: что изменилось и зачем. Не копировать commit subjects механически.
- Включать только значимые изменения и группировать их по release.

## Categories

Использовать только непустые релевантные категории:

- Added / Добавлено;
- Changed / Изменено;
- Deprecated / Устарело;
- Removed / Удалено;
- Fixed / Исправлено;
- Security / Безопасность;
- Breaking Changes / Ломающие изменения.

Не вводить новые категории, если они явно не определены правилами текущего repository.

## Breaking changes

Выносить несовместимые изменения в отдельный заголовок Breaking Changes. Для каждого пункта указать:

1. что изменилось;
2. почему;
3. что должен сделать пользователь для миграции.

При большом объёме добавлять ссылку на Migration Guide.

## Release example

~~~markdown
# Changelog

Все значимые изменения проекта документируются в этом файле.

## [Unreleased] / Невыпущенное

### Added
- Добавлена авторизация через OAuth2 для API-клиентов.

## [2.0.0] - 2025-09-01

### Breaking Changes
- Удалён endpoint /v1/users. Перейдите на /v2/users.
- Поле created_at теперь использует ISO 8601 вместо UNIX timestamp.

### Added
- Добавлен endpoint /v2/users с расширенным contract.

### Fixed
- Исправлено обновление профиля при пустом optional field.
~~~

## Review

- Сверить changelog с фактическим диффом и доступной локально историей. Если история влитых MR недоступна, не заявлять полноту changelog как проверенный факт.
- Проверить version в pyproject.toml и других manifests.
- Проверить дату release и отсутствие секции Unrealized вместо Unreleased.
- Убедиться, что запись в разделе Security не раскрывает детали эксплуатации до выпуска исправления.
- Не создавать теги и не выполнять push без явного разрешения.
